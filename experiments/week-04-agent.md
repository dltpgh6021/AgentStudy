## 2. 질문과 학습 개념의 적용

실제로 입력한 질문:

> repo-scout 명령을 실행하면 입력한 저장소 경로가 어떤 함수들을 거쳐 Markdown 파일로 저장되나요? 주요 파일의 역할도 설명하세요.

| 개념 | 구현 및 이번 기록에서 확인한 부분 | 아직 확인하지 않은 부분 |
|---|---|---|
| Cognitive Architecture / CoALA | 작업 기억, 파일 도구, 의사결정 순환을 분리. 선택한 부모의 관찰이 다음 단계로 전달됨 | 장기 기억 자동 회상·학습은 미구현 |
| CoT에서 착안한 단일 경로 | cot 모드는 코드에 구현돼 있음 | 실제 모델의 cot 실행·비교는 미실행 |
| ToT | 단계별 후보 3개 생성·평가, 후보 1개 유지, 선택한 부모에서 다음 후보 생성 | 원 논문 전체 재현, 되돌아가기, 여러 부모 유지는 미구현 |
| Reasoning Diversity | 데이터 흐름·모듈 연결·검증 관점을 후보에 부여 | 관점 지시가 의미적 다양성이나 성능 개선으로 이어졌는지는 미검증 |

상태로 저장하는 것은 짧은 분석 결론과 도구 관찰이다. 모델의 비공개 사고 과정을 수집한 기록이 아니다.

## 5. 후보 생성과 선택 과정

점수는 같은 모델이 매긴 관련성·근거·범위 각 0~2점의 합이다. 정답률이나 사람의 채점 결과가 아니다.
인용이 없거나 해당 후보가 관찰하지 않은 위치를 인용하면 선택 대상에서 제외한다. 이번 후보 6개는 모두 이 위치 검사를 통과했다.

| 후보 | 부모 | 실제로 새로 수행한 행동 | 관련성 / 근거 / 범위 | 합계 | 선택 |
|---|---|---|---|---:|---|
| d1-c1 | root | cli.py 1~30줄 읽기 | 2 / 2 / 1 | 5 | 선택 |
| d1-c2 | root | analyzer.py 1~60줄 읽기 | 1 / 1 / 1 | 3 | 제외 |
| d1-c3 | root | pyproject.toml 1~19줄 읽기 | 1 / 2 / 0 | 3 | 제외 |
| d2-c1 | d1-c1 | analyzer.py 1~60줄 읽기 | 2 / 2 / 1 | 5 | 선택 |
| d2-c2 | d1-c1 | def render_markdown 검색: 115줄 1건 | 2 / 1 / 1 | 4 | 제외 |
| d2-c3 | d1-c1 | pyproject.toml 1~19줄 읽기 | 2 / 2 / 1 | 5 | 제외 |

1단계는 최고점인 d1-c1이 선택됐다. 2단계는 d2-c1과 d2-c3이 동점이었다.
choose_candidate가 최고점 중 먼저 생성된 후보를 유지하므로 d2-c1이 선택됐다. d2-c1이 의미적으로 더 우수하다고 입증한 결과는 아니다.
다음 단계의 작업 기억은 선택한 부모의 관찰만 이어받았다. 버린 형제의 관찰을 최종 답변의 근거로 합치지 않았다.

## 6. 최종 답변의 정적 대조 검토

모델은 main → scan_repository → render_markdown → 파일 저장의 흐름을 설명했다.
원본 스냅샷과 대조한 아래 평가는 사후 정성 검토이며, 사전에 정의한 벤치마크의 정확도 점수가 아니다.

| 검토 항목 | 관찰과 판정 |
|---|---|
| cli.py 역할 | 인자 파싱과 전체 호출·저장을 연결한다는 설명은 코드와 일치한다. 9·17·20·24줄로 확인 가능 |
| analyzer.py 역할 | 스캔·역할 분류·렌더링을 담당한다는 큰 설명은 코드와 일치한다. 다만 Agent는 핵심 함수 본문을 읽지 않았음 |
| pyproject.toml 역할 | 최종 답변에서 별도 설명이 누락됐다. 버린 후보들은 명령 진입점 설정을 확인했지만 최종 선택 경로에는 포함되지 않음 |
| 실행 흐름 | cli.py의 20줄과 24줄에서 스캔 → 렌더링 → 저장 연결을 확인할 수 있음 |
| 인용의 위치 유효성 | 최종 인용 5개 모두 관찰한 범위 안에 있음 |
| 인용의 의미적 충분성 | 부분적. analyzer.py 60줄은 describe_role의 선언이며 스캔·렌더링 본문이나 필터 적용의 근거는 아님 |
| 함수 상세 분석 | 미완료. scan_repository는 73줄, render_markdown은 115줄에서 시작하지만 최종 선택 경로는 1~60줄까지만 읽음 |

최종 답변은 큰 호출 흐름을 설명했지만, 주요 파일 3개를 모두 설명하거나 상세 동작을 충분히 근거화하지는 못했다.
모델도 함수 상세 구현을 확인하지 못했다는 한계를 보고서에 밝혔다.

## 7. 실패·한계 분석

### 계획과 실제 읽기 범위의 불일치

d2-c1은 scan_repository 상세 구현을 확인하겠다고 계획했지만 start_line=1로 읽었다.
도구의 60줄 제한 때문에 함수 본문에 도달하지 못했다. 단순히 더 오래 읽히는 것보다 함수 위치를 검색하고 그 위치를 다음 읽기에 연결하는 개선이 필요하다.

### 관점과 입력 자료의 불일치

세 번째 관점은 테스트·기대 동작·예외 처리였다. 그러나 --include에 테스트 파일이 없어서 테스트 파일의 직접 조회는 불가능했다.
실제로 해당 후보는 두 단계 모두 설정 파일을 읽었다. 관점 지시만의 문제로 단정할 수 없으며, 입력 범위를 먼저 바로잡아야 한다.
이 자료 제한 때문에 이번 실행으로 Reasoning Diversity의 효과를 판단할 수 없다.

### 자체 평가와 동점 처리의 한계

함수 본문을 확보하지 못한 후보도 5점을 받았다. 위치 유효성 검사는 주장과 근거의 의미적 일치까지 검사하지 않는다.
새로운 정보 기여·남은 질문 해결 여부를 평가하거나 별도 검토자를 두는 개선을 검토할 수 있다.
동점에서 첫 후보가 선택되는 편향도 기록해야 한다.

### 반복 실행과 비교 자료의 부족

현재 실제 기록은 한 저장소·한 질문·한 모드의 1회 실행뿐이다.
tot/cot 비교, 반복 표본, 독립 평가, 사전 정의 정답표가 없으므로 정확도 향상·비용 우위·일반적인 효용을 주장하지 않는다.
같은 응답에서 생성한 후보들은 독립 rollout도 아니다.

## 8. 현재 선택 정책과 코드 변경 상태

- perspectives: cot는 공통 관점 1개, tot는 공통 관점 3개, diverse는 서로 다른 관점 3개를 반환한다.
- score_candidate: 관찰한 인용이 있는 후보의 관련성+근거+범위를 합산한다. 관찰하지 않은 인용이 있으면 제외한다.
- choose_candidate: 적격 후보 중 최고점을 선택하고 동점이면 앞선 후보를 유지한다.
- 정책 가중치 변경 실험: 미수행. 이번 정리에서는 실제 Agent의 선택 정책을 변경하지 않았다.
- 테스트 보완: 모의 모델이 의도적으로 실패할 때 완료 상태를 남기던 부분을 오류 상태로 수정했다. 기존 실패 테스트에서 성공 3회·오류 1회를 확인하도록 보완했다.
- 위 테스트 보완은 프로그램 검증의 정확성을 높이는 수정이며, 실제 모델 성능이 개선됐다는 결과가 아니다.

## 9. 다음 실험 계획 — 아직 미실행

1. 먼저 같은 세 파일·질문·모델로 tot와 diverse를 실행해 탐색 경로와 설명 차이를 비교한다. 기존 예제와 비교할 때 파일 해시도 확인한다.
2. 테스트 관점을 검토할 별도 실험에서는 테스트 파일을 포함하되, 비교하는 모든 모드에 같은 자료를 제공한다. 기존 3파일 결과와 직접 성능 비교하지 않는다.
3. 함수 위치 검색 후 본문 읽기, 또는 선택 정책 가중치 중 한 가지만 바꿔 새 실행 전후를 비교한다.
4. 반복 횟수와 채점 기준을 실행 전에 정하고, 모델의 자체 점수와 사람의 검토 결과를 분리한다.

tot 실행 예시(명령을 적었다고 실행 완료를 뜻하지 않음):

```powershell
.\.venv\Scripts\python.exe run_agent.py analyze . --include src/repo_scout/analyzer.py src/repo_scout/cli.py pyproject.toml --mode tot --model gemini-3.5-flash-lite -o outputs/agent-tot-01
```

## 10. 결론

1. 깊이 2·분기 3의 후보 탐색과 자동 평가·선택은 실제 Gemini 응답 5회로 완료됐고, 저장된 평가를 사용해 동일 선택 경로를 재현했다.
2. 최종 답변의 큰 실행 흐름은 맞았지만 함수 본문 미조회, 파일 역할 누락, 테스트 자료 부재, 자체 평가·동점 처리의 한계가 확인됐다.
3. 현재 결과는 구현의 동작과 개선 지점을 보여 준다. 관점 다양성의 성능 개선 여부는 자료를 통제한 후속 비교 실험으로 판단해야 한다.

## 11. 저장소 전체 점검

정리 당시 Git 추적 파일 20개를 확인했다. 비밀 설정·가상환경·강의 PDF는 저장소에서 제외돼 있어 점검·공유 대상에 넣지 않았다.

| 파일 묶음 | 점검 결과 |
|---|---|
| .gitignore, .env.example, pyproject.toml | 제외 규칙·설정 예시·패키지 설정 확인. .env.example의 키 자리표시는 의도된 예시이므로 실제 키로 채우지 않음 |
| run_agent.py, src/repo_scout/__init__.py | 실행 진입점·버전 확인. 미완성 구현 발견 없음 |
| agent.py, gemini.py, policy.py, repo_tools.py | 호출·탐색·도구·인용 검사·오류 처리를 확인. 위 한계는 명시하고 실행 알고리즘은 변경하지 않음 |
| cli.py, analyzer.py | 실제 분석 예제로 유지. 스냅샷·현재 파일 해시 일치 확인 |
| tests/test_agent.py, tests/test_analyzer.py | 모의 데이터와 실제 결과를 구분. 실패 모의 응답 상태 기록 보완, 총 11개 테스트 확인 |
| README.md, AGENT_START.md | 실제 결과 요약, 실험 범위, 읽는 순서와 업로드 절차를 갱신 |
| experiments/week-04-agent.md | 빈 결과표·정책 설명·결론을 기존 기록에 근거해 작성. 미실행 항목은 상태를 명시 |
| outputs/agent-diverse-01의 report.md·trace.json·calls.json·snapshot.json | 모든 JSON과 응답 형식·부모 상속·점수·인용·사용량을 대조. 원본 4개 파일은 수정하지 않음 |

원본 보고서와 로그의 내용은 과거 실행의 증거이므로 사후 검토 결과에 맞춰 고치지 않았다.
실험 문서에는 자동 생성 결과와 사후 검토·후속 계획을 구분해 기록했다.
